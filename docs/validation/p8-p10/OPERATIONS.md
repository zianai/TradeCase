# Controlled local operation

Use the locked Python environment (`uv sync --frozen --extra platform --extra dev`) and frontend lock. Do not load a real `.env` into acceptance commands. `ops/p8_browser_acceptance.py --evidence NEW_DIR` provisions a new disposable API/database/user, runs Next on loopback and real Chromium, then terminates only its children. Set PLAYWRIGHT_BROWSERS_PATH to an already installed browser cache. It requires a built frontend. `ops/p8_tls_acceptance.py --evidence NEW_DIR` separately verifies disposable loopback TLS. Neither command needs model credentials.

For the independent PG/Redis topology, follow `ops/README.md` and `ops/compose.yaml`. Install a dedicated random DB secret outside Git, keep user tokens in mode-0600 files, publish only 127.0.0.1, and preserve disabled live-model/public-fetch/outbound settings. Do not replace the current runtime with the synthetic acceptance configuration. Public exposure, real domain TLS, paid calls and outbound credentials need separate authority. Production secret-store integration is not claimed installed.

Read `GET /api/health` without secrets. Authenticated admin `GET /api/metrics` returns tenant-scoped case_counts, task_counts, outbound_counts, pending_approvals and external_sends. A loopback monitor can poll these; no alert is sent outside the machine by this release. Treat accumulating READY/PENDING tasks, unexpected FAILED tasks, long-lived pending approvals, DELIVERY_UNCERTAIN/SENDING effects and a backup command failure as operator review conditions. Compare successive samples and inspect task/events for duration; counts alone do not establish SLA breaches. External_sends must remain zero in synthetic acceptance.

Rotate a user token with `python -m tradecase.platform.cli rotate-token --user-id USER --token-file ADMIN_FILE --new-token-file NEW_FILE`. The old token stops authenticating immediately; distribute the replacement only through the authorized secret channel. `revoke-user --user-id USER --token-file ADMIN_FILE` disables that identity; re-provisioning is separate. Keep a different admin recovery credential available. Do not print token file contents into logs or reports. CE/LC tokens are distinct and are never reused here.

For retention, run `python -m tradecase.platform.cli maintenance plan --token-file ADMIN_FILE --before ISO_UTC`, then inspect the exact closed Case/version. `maintenance purge` requires `--case-id`, `--version`, `--idempotency-key`, and remains dry-run without `--apply`. Pending tasks/workflows/visual receipts/outbound uncertainty prevent purge. Run `maintenance verify`; orphan GC requires writers quiesced and explicit opt-in. Real data deletion requires the data owner's current retention decision.

Backup: quiesce writers, use `ops/backup.sh NEW_BACKUP_DIR`, retain the old release and encrypt/restrict the resulting archive outside Git. On backup failure the scripts deliberately leave writers stopped; reconcile before restart. Restore only to a new Compose project/volumes using `ops/restore.sh BACKUP_DIR NEW_PROJECT`, verify every object hash and checkpoint/approval subject, and reconcile all unknown mail effects before workers resume. Redis is not the task source of truth. Do not downgrade a live database; rollback means restoring a verified backup with its matching release. Disposable migration up/down testing is not a production rollback authorization.

Reproduce local checks: `make check`; `make contract`; `P7_OFFLINE_DOCKER=1 python ops/verify_infrastructure.py`; frontend `npm run build`; then the two local acceptance scripts. Use an empty credential environment and loopback-only egress control. `ops/p8_ce_http_smoke.py --url http://127.0.0.1:PORT --token-file PRIVATE_FILE` consumes the existing 1.0.0 fixture using unique identifiers and validates hash/QA/idempotency/cancel. It never enables a paid provider. The coordinator runs simultaneous consumers with separate business DBs.

For pilot evaluation, obtain the hash-only `/api/cases/{id}/pilot-export-scope` and have the authorized operator pin that exact tenant/case/dataset/input_hash/rights_hash/classification using the existing P7 private-record mechanism. Never copy an intake grant into export scope. After adding sources or changing rights, request a new exact subject grant; do not relabel unknown source material synthetic. `pilot-export` rechecks subject and authorization before returning.
