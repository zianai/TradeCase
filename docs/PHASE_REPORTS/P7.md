## 风险分级和V2门槛

| 等级 | 问题 | 处理及进入V2前门槛 |
|---|---|---|
| 高 | 没有真实授权询盘/真实商品的人审样本，不能评价主体匹配、商业判断或回复质量 | 获取有权处理的数据，按证据覆盖、错误主体关联、人工修正数逐项评审 |
| 高 | 本网络下直接Reader被保留DNS拒绝；宿主web和浏览器成功不等于Reader成功 | 在可解析真实公网地址、策略不弱化的环境执行成功/失败端到端及robots验证；透明代理使用需明确安全设计 |
| 高 | 监管规则来源当前性/适用性不完整，系统仅供风险研究 | 由具备相应能力的人员核对产品范围、规则版本与官方正文，验证不完整资料不可pass |
| 中 | Claude Agent链路未验证；用户未批准本次调用 | 用户之后主动授权并在合适认证/权限配置下实跑，保留用量与结果；不以登录状态代替运行证据 |
| 中 | Web Access的完整许可证文本缺失，且代理可控制浏览器 | 获取可商用许可确认，独立审计认证/隔离和写操作限制，再决定是否集成 |
| 高 | 真实历史招标Case不会自动判定截止日期，且固定回复模板不适配招标 | 增加有证据绑定的截止/时区和附件解析、地区资格核验及人工审批，再用真实卖家资料验证 |
| 中 | 真实历史公告只来自同一买方且全部过期；另5组业务问题是合成的 | 扩充有权处理的当前客户样本、独立人工复核、记录真实token/费用；未测不能填0 |
| 低 | Crawl4AI、Windows、远程CI未验证 | 按真实需求评估，不作为目前添加复杂依赖的理由 |

No-Go针对V2产品化/扩展，不禁止继续V1真实样本验证与网络兼容性研究。实际外部邮件发送0、外部账号写操作0；只读公开网页及隔离本机浏览器测试已执行，Claude新增调用0。每一阶段的限制与完成条件见上述证据，不能把合成任务或浏览器演示宣传成真实客户成交能力。
