# TradeCase Web 工作台

Next.js + TypeScript 的 Case 工作台。界面访问同源 `/api`；服务端代理将请求转到 `TRADECASE_API_URL`。数据、租户权限、审批、版本及任务状态均以 Python 业务服务为准。

## 启动

需要 Node.js 24 或更新的兼容版本、运行中的 TradeCase API，以及管理员签发的工作区访问令牌。

```bash
npm ci
TRADECASE_API_URL=http://127.0.0.1:8800 npm run dev -- --port 3300
```

打开 `http://127.0.0.1:3300`，在「连接设置」输入访问令牌。只保存在当前标签页的 `sessionStorage`，通过 Authorization 请求头发送，不写入 URL 或构建产物。退出连接后清空本地视图。

生产构建：

```bash
npm run build
TRADECASE_API_URL=http://api:8000 npm start -- --port 3000
```

Dockerfile 使用 Next standalone，非 root 用户运行；代理地址在运行时读取。正式部署使用 HTTPS，API 不应直接公开给互联网；参见仓库 ops/ 文档。

## 已实现交互

- 工作台实际计数、服务端询盘搜索、状态/标签筛选与分页；显式选择新建/失败案件批量开始调查；文本/手动/UTF-8 `.eml` 或 `.txt` 导入，按服务限额校验。
- 明确标识合成案例；只有服务开启演示时显示合成导入选项。
- Case 原始询盘与事实、推断、未知分层；来源、引用、采集时间、快照 hash 和纯文本快照。
- 人工快照导入、原文逐字引用、待核实主张；人工导入明确不算在线抓取。
- 高级人工复核仅对审核员/管理员显示；逐条检查来源许可与角色、实体、评分依据和规则，保存不可变复核版本后显式重新计算。确认选项默认均为 false。
- 市场与平台风险、规则版本；报告 JSON/Markdown/PDF 导出。
- 草稿编辑、历史版本、逐行差异、剪贴板复制；专业/简洁/友好三种本地语气预览只调整称呼与结尾，不改写正文事实或签名。预览未保存，必须通过现有新版本保存重新审核；审批始终绑定内容 hash 与 Case 版本。
- 批准、拒绝、要求修改、要求补证据；正文修改后展示旧批准失效。
- 单任务重试、持久事件与 SSE 重连补拉；五秒轮询用于恢复断线状态。
- 跟进创建、完成、推迟；标题、标签和优先级整理；同邮箱域名的案件仅提示关联、不自动合并。
- 外发默认关闭。开启后仍需独立发送审批、精确收件人与版本、明确确认及手动执行；不确定回执不重发。审核员/管理员可填写原因取消待执行动作，服务端重新校验角色、版本与状态。
- 版本化内部知识的文本/文件登记、范围、有效期、历史查看和修订；资料始终标为用户提供且未核实，与案件证据分开。
- 来源、模型、预算与保留配置展示；角色权限由 API 服务强制执行。

未连接来源会显示未接入。真实模型、邮件账户和付费来源均不因打开界面而自动启用。

## 测试

```bash
npm run typecheck
npm run build
npx playwright install chromium
# 对测试夹具的独立 UI 安全与键盘 / 窄屏检查
npx playwright test tests/ui.spec.ts
# 真实本地 API + DB 的完整浏览器流程；服务必须开启合成演示
TRADECASE_E2E_TOKEN_FILE=/absolute/path/to/local-token-file npm run test:e2e
```

默认测试地址 `http://127.0.0.1:3300`，可由 `TRADECASE_WEB_URL` 改写。令牌文件只在测试进程中读取，不输出；禁用 Playwright trace 以免网络凭据写入 trace。live-e2e 用显式合成案例完成审批与跟进，并验证 outbox 为空，绝不调用发送接口。未提供令牌文件时该项显示 skipped，不算已验证。

浏览器执行证据位于 `design/rounds/01/`，是合成数据的实际运行截图。设计方向为 AI 暂定，未声明用户设计批准、法律合规认证或真实业务转化效果。独立审核及系统级限制由主交付报告记录。
